       - Startup: call init_db(), then create PriceCache(), create_market_data_source(cache),

       stream_router = create_stream_router(price_cache)
       BUT the cache is created inside lifespan, so create it outside lifespan at module level
       as a module-level variable so create_stream_router can be called before lifespan runs.

       Correct approach: create price_cache and market_source as module-level singletons
       (not inside lifespan), then lifespan just calls source.start() / source.stop().
       Register stream_router = create_stream_router(price_cache) at module level before
       app.include_router(stream_router, prefix="/api").

    5. Define GET /api/health endpoint returning {"status": "ok"} with status_code=200.
       This endpoint requires no auth and no DB access — it must respond even if DB init

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → /api/health | Unauthenticated; returns no sensitive data |
| client → /api/stream/prices | Unauthenticated SSE; emits only public price data |
| env → app config | .env loaded from filesystem; MASSIVE_API_KEY is the only secret in scope |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-03 | Information Disclosure | /api/stream/prices | accept | Streams simulated/public market prices; no PII or account data in this phase |
| T-01-04 | Denial of Service | lifespan startup | mitigate | init_db() and source.start() failures will raise at startup, preventing the app from accepting requests in a broken state — fail-fast is correct behavior |
| T-01-05 | Information Disclosure | .env loading | mitigate | load_dotenv() loads from filesystem path derived from __file__; API key never logged or returned by any endpoint |
</threat_model>
