**`GET /watchlist` handler (API-04):**
- Open DB, `SELECT ticker FROM watchlist WHERE user_id='default' ORDER BY added_at`.
- For each ticker: `price = price_cache.get_price(ticker)` (returns float | None).
- Return `{"watchlist": [{"ticker": t, "price": p} for t, p in results]}`.

**`POST /watchlist` handler (API-05, D-15):**
- Normalize ticker: `ticker = request.ticker.upper().strip()`.
- Open DB: check if ticker already exists with `SELECT id FROM watchlist WHERE user_id='default' AND ticker=?`.
- If exists: raise `HTTPException(400, detail=f"Ticker {ticker} already in watchlist")` per D-06/D-07.
- Insert: `INSERT INTO watchlist (id, user_id, ticker, added_at) VALUES (?, 'default', ?, ?)`.
- After DB commit: `await market_source.add_ticker(ticker)` per D-15.
- Return `{"status": "ok", "ticker": ticker}`.

**`DELETE /watchlist/{ticker}` handler (API-06, D-16):**
- Open DB: check if ticker exists with `SELECT id FROM watchlist WHERE user_id='default' AND ticker=?`.
- If not exists: raise `HTTPException(404, detail=f"Ticker {ticker} not in watchlist")` per D-06/D-07.
- Delete: `DELETE FROM watchlist WHERE user_id='default' AND ticker=?`.
- After DB commit: `await market_source.remove_ticker(ticker)` per D-16.
- Return `{"status": "ok", "ticker": ticker}`.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| HTTP client -> POST /api/watchlist | User-supplied ticker string used in DB insert and market_source call |
| HTTP client -> DELETE /api/watchlist/{ticker} | Path parameter ticker used in DB delete and market_source call |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-03-01 | Tampering | POST /api/watchlist ticker input | mitigate | Normalize ticker to uppercase + strip whitespace before DB insert and market_source call. Pydantic validates field is a string. |
| T-02-03-02 | Tampering | DELETE /api/watchlist/{ticker} path param | mitigate | FastAPI path param is a plain string; DB query uses parameterized statement — no SQL injection risk. |
| T-02-03-03 | Denial of Service | market_source.add_ticker on each POST | accept | Single-user app; no rate limiting needed at this stage. market_source.add_ticker is a no-op if already present. |
| T-02-03-04 | Spoofing | user_id hardcoded | accept | Same as portfolio plan — single-user, no auth in scope. |
</threat_model>
